# 项目数据格式（project-manifest）

统一项目清单是画布与 Remotion 渲染之间的唯一契约。前端把画布节点组装成一份
`manifest` 对象，POST 给 `/api/render/remotion`；Remotion 合成完全由这份 manifest 驱动，
没有任何单片硬编码。

纯函数实现在 [`shared/manifest.js`](../shared/manifest.js)，TypeScript 类型在
[`shared/manifest.d.ts`](../shared/manifest.d.ts)，前端、Remotion 合成、服务端与测试共用。

## 时间约定（重要）

所有时间统一用**秒**；Remotion 内部按 `composition.fps` 折算为帧。

| 字段 | 含义 |
|---|---|
| `shots[].start` / `shots[].end` | **源素材**的裁剪入点 / 出点（秒）。镜头按 `order` 顺序首尾**硬切**拼接。 |
| `audioTracks[].start` / `end` | **成片时间轴**上的绝对位置（秒）。 |
| `subtitles[].start` / `end` | **成片时间轴**上的绝对位置（秒）。 |

> 注意 `shots` 与 `audioTracks`/`subtitles` 的 `start/end` 语义不同：前者是源素材裁剪，
> 后者是时间轴绝对位置。混淆会导致声音/字幕错位。

## 结构

```jsonc
{
  "project": { "id": "project-id", "title": "项目标题" },
  "composition": { "width": 1280, "height": 720, "fps": 24 },
  "shots": [
    {
      "id": "shot-001",
      "name": "镜头名称",
      "file": "/library/videos/xxx.mp4", // 相对 /library 的素材地址
      "start": 0,      // 源素材入点（秒）
      "end": 5,        // 源素材出点（秒）
      "volume": 0,     // 镜头原声音量，0=静音
      "order": 1       // 排序
    }
  ],
  "audioTracks": [
    {
      "id": "audio-001",
      "type": "dialogue",   // dialogue | sfx | bgm
      "file": "/library/audio/xxx.mp3",
      "start": 0,           // 时间轴绝对起点（秒）
      "end": 3,             // 时间轴绝对终点（秒）
      "volume": 1,
      "fadeIn": 0,
      "fadeOut": 0,
      "ducking": false,     // 仅 bgm：对白期间自动压低
      "loop": false,
      "speaker": "角色名"
    }
  ],
  "subtitles": [
    {
      "id": "subtitle-001",
      "text": "字幕内容",
      "start": 0,           // 时间轴绝对起点（秒）
      "end": 3,             // 时间轴绝对终点（秒）
      "speaker": "角色名"
    }
  ],
  "output": {
    "endFadeToBlack": 0.6,  // 结尾淡黑时长（秒）
    "subtitleStyle": "default"
  }
}
```

## 路径安全

- 素材地址支持 `/library/videos/a.mp4`、`library/audio/b.mp3`、含缓存串的 http 地址等，
  由 `normalizeAssetPath()` 归一化为 `videos/a.mp4` 这样的相对路径供 Remotion `staticFile` 使用。
- 服务端 `resolveAssetPath()` 会把相对路径解析到 `library/` 内，并**阻止路径穿越**
  （解析结果必须严格位于 `library/` 之内），否则拒绝渲染。
- 渲染前会做**素材存在性检查**，缺失素材会在成片节点上列出，不会盲目启动渲染。

## 总时长

成片总时长 = `max(镜头拼接总时长, 所有音轨结束点, 所有字幕结束点)`，
保证末尾的音效 / BGM / 字幕不会被截断。由 `computeTotalDurationSec()` 计算，
再通过 Remotion 的 `calculateMetadata` 动态设置 `durationInFrames`。

## 可扩展性

结构预留了扩展空间：后续可增加转场、调色、字幕样式、多角色配音等字段，
只需在 `shared/manifest.*` 与 Remotion 合成中增量支持，无需改动画布主流程。

## 统一画布短视频复刻

当前短视频复刻以普通画布节点保存。核心分析节点和自动生成节点使用稳定的来源字段：

```jsonc
{
  "nodes": [
    {
      "id": "analysis_xxx",
      "type": "Video Analysis",
      "parentIds": ["source_video", "product_image"],
      "inputPortByParentId": {
        "source_video": "source-video",
        "product_image": "product-reference"
      },
      "videoAnalysis": {
        "status": "completed",
        "inputRefs": {
          "videoNodeId": "source_video",
          "productNodeIds": ["product_image"],
          "characterNodeIds": [],
          "sceneNodeIds": []
        },
        "result": { "global": {}, "shots": [] }
      }
    },
    {
      "id": "analysis_xxx__shot_01__video",
      "type": "Video",
      "origin": { "type": "video-remix", "analysisNodeId": "analysis_xxx", "role": "video" },
      "inheritedReferences": { "productNodeIds": ["product_image"], "characterNodeIds": [], "sceneNodeIds": [] }
    }
  ],
  "groups": []
}
```

- `inputPortByParentId` 是连接语义的来源，`parentIds` 只负责持久化边集合，不能用数组顺序推断角色。
- `videoAnalysis.result` 只保存一份全局约束和每个镜头的双提示词；关键帧、镜头视频和 Render
  节点都复用现有生成与渲染链路。
- 上游参考素材变化会把分析节点置为 `outdated`，并把派生节点标为 `needsUpdate`；不会自动重复
  发起计费生成。手动编辑的提示词保存为 `promptSource: "user"` 与 `promptLocked: true`。

## 兼容的项目级短视频复刻记录

旧版短视频复刻仍以 `nodes` 平级的 `videoRemixes[]` 记录保留，便于打开旧项目和保存迁移标记：

```jsonc
{
  "nodes": [],
  "videoRemixes": [
    {
      "schemaVersion": 1,
      "id": "remix_xxx",
      "title": "产品宣传片复刻",
      "state": { "remixId": "remix_xxx", "stage": "source_pending" },
      "createdAt": "2026-08-01T00:00:00.000Z",
      "updatedAt": "2026-08-01T00:00:00.000Z",
      "sourceCanvasNodeId": "可选：来源画布视频节点",
      "finalCanvasNodeId": "可选：历史发送回画布后的普通视频节点",
      "canvasMigrationVersion": 1,
      "canvasAnalysisNodeId": "迁移后对应的 Video Analysis 节点"
    }
  ]
}
```

- 旧记录中的源视频、人物、场景和产品参考会转换为普通媒体节点，并连接到固定输入端口。
- 有完整 Shot 分析时，加载项目会同步创建关键帧、镜头视频和最终 Render 节点；没有分析结果时只
  创建可继续编辑的分析节点。
- 打开含旧 `Video Remix` 容器节点的项目时，客户端先幂等迁移到 `videoRemixes[]`，再执行上述
  画布迁移；首次落盘前，后端仍保留一次 `.pre-video-remix-workspace-v2.bak` 迁移前备份。
- 项目改名、素材归档和图片回收站都会递归处理 `videoRemixes[].state` 中的项目素材地址，
  避免复刻任务仍引用的文件被误删。

## 项目图片回收站

画布删除项目内的图片节点时，不直接永久删除本地文件。后端在项目根目录按需创建：

```text
<项目目录>/
├─ project.json
├─ images/
└─ .trash/
   ├─ index.json
   └─ files/<回收站条目 ID>/images/
```

- `index.json` 保存删除时间、7 天到期时间、原画布节点快照和原文件相对路径。
- 删除最后一个有效引用时，图片及同名 JSON 元数据从 `images/` 移除；仍被其他画布节点、
  项目封面或短视频复刻任务引用的文件继续保留，同时为回收站创建独立备份。
- 恢复操作同时恢复原文件和画布节点；永久删除只清理对应回收站副本。
- 后端启动时以及运行期间每小时清理一次已到期条目。
- `.trash/` 属于持久化项目用户数据，不进入 Git 或安装包，也不会因应用升级被覆盖。
