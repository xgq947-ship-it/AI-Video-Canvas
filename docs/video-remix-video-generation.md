# Video Remix 镜头视频生成

镜头视频层位于关键帧确认与 Timeline 之间。它复用现有视频 Provider、
`/api/generate-video`、项目素材目录和生成任务日志；本地时长校准复用安装包内置的
FFmpeg / FFprobe，不增加最终用户运行前置条件。

## 进入条件

视频页只有在以下条件全部满足时才允许提交生成：

- Prompt 已确认；
- 计划内关键帧全部生成并由用户确认；
- Prompt 确认的目标视频模型仍与当前模型一致；
- 源视频画幅受目标模型支持；
- 每个 Shot 时长能由目标模型时长档位安全覆盖。

关键帧确认不会自动开始视频生成。用户可生成全部未完成 Shot，也可逐 Shot 生成。
前端批量并发上限为 2，底层仍经过现有 Provider 调度器。

## Provider 能力与输入选择

`getVideoProviderCapabilities()` 为每个模型提供统一能力描述：

- 图生视频；
- 首帧、尾帧；
- 多参考图、人物参考；
- 原生声音；
- 最长时长、最大参考图数量及参考模式。

提交输入按实际协议选择：

- 支持首尾帧：Start + End；
- 只支持首帧：Start；
- 支持多参考：Start + 当前 Shot 的人物 / Look + 场景 + 道具，按模型上限截取；
- 仅支持参考素材：按当前 Shot 资产构建参考图集合。

视频 Prompt 使用已确认的 Optimized Video Prompt，内容继续包含 Frame、Motion、
Camera、Timing、Audio Blueprint 以及当前人物、场景和道具。调试面板同时展示 Raw、
Resolved、Optimized 与真正提交的版本；用户手动编辑提交版本时，只使当前 Shot 视频
失效，不会重新生成关键帧。

## 时长锁定与本地校准

原 Shot 时长始终是目标时长。系统优先选择“不短于目标”的最小 Provider 档位，生成后
使用内置 FFmpeg 裁剪。例如 3.2 秒 Shot 使用 4 秒档，随后裁剪为 3.2 秒。

当目标略长于模型最大档位时，只允许不低于 `0.85x` 的轻微放慢；超过该范围时在提交前
阻止生成，避免大幅变速。校准输出写入：

```text
library/projects/<project>/video-remix/<remix>/videos/
```

校准接口只接受当前项目目录中的源视频，输出采用 H.264 / AAC，并按输入文件状态、目标
时长和裁剪点缓存。校准失败会保留原始生成结果；文件缺失、损坏或时长不足时要求重新
生成，其余本地错误可直接重试校准而不会再次计费。

## 状态、缓存与恢复

每个 Shot 持久化模型参数、Prompt 层、参考图、时长计划、输入哈希、提交 ID、原始视频、
校准视频、错误和确认时间：

- 输入未变化时复用已有结果；
- 修改视频模型、画幅、分辨率或声音选项，只使视频层及其下游失效；
- 修改上游 Prompt、资产或关键帧，会使对应视频、确认、Timeline 与成片失效；
- 异步结果必须匹配 `inputHash`，旧任务不能覆盖新的 Prompt 或配置；
- 已提交但结果未知时设置 `retryBlocked`，避免自动重复扣费；
- 生成超过 30 分钟仍无结果时标记“提交状态未知”，用户核对平台历史后再重试；
- 本地校准中断时保留原始视频，应用重启后可安全继续校准；
- 打开视频页时会按持久化的生成节点 ID 查询当前项目素材，恢复已完成结果。

## 人工确认门

每张 Shot 卡片同时显示确认首帧、校准后视频、实际输入模式、时长处理、声音模式和
Prompt 调试信息。单 Shot 失败不影响其他结果，并支持单项重试、只重试失败项、逐项确认
与全部确认。

只有所有 Shot 都完成本地时长校准并由用户确认后，`videoReview.confirmed` 才为 `true`。
Timeline / Remotion 阶段必须读取该确认门；生成成功本身不会自动进入成片。

未登录 Gemini 不影响视频计划、Prompt 编辑、缓存恢复、时长校准、界面确认或本地测试。
只有用户实际选择 Gemini Web、Google Flow 等需要网页登录的 Provider 并提交生成时，
才需要对应登录态；认证错误保留在当前 Shot，登录后可继续。
